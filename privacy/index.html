Sprint Scope Guard

Sprint Scope Guard is a Jira Cloud Forge app. It reads Jira sprint, issue, and changelog data for the current-sprint scope audit and uses Forge-hosted storage for application state.

  • Forge-hosted storage: Forge KVS stores app settings and governance records. Records can include Jira issue summaries, statuses, priorities, removal details, and account IDs; retained historical records can include display names. This data is stored in Forge-hosted storage, not an external Neural Void database. See Atlassian's Forge storage reference.
  • Exports and manual webhook tests: CSV, JSON, and Markdown exports are generated in the browser. A project administrator may manually test a configured Slack or Microsoft Teams webhook; the test sends generic test text and a timestamp. The app does not automatically send scope or threshold notifications. The Forge egress allowlist is hooks.slack.com and *.webhook.office.com.
  • Retention and residency: After uninstallation, Forge-hosted data is retained for up to 28 days. A new installation can be linked to the old data only when recovery is requested within 21 days; a reinstall does not automatically restore it. Forge documents hosted-storage residency behavior in its data-residency documentation.
  • Operational logs: Our application messages contain only an allowlisted operation and code, a release label, a random per-request UUID, and duration. They do not contain Jira content, user data, site data, webhook data, or hashes. Forge also adds platform metadata such as installation site, app version, environment, and invocation identifiers, so logs are not anonymous. Developer access depends on the customer's log-sharing settings and the applicable Atlassian cloud offering. Forge app logs are available for 30 days; see Forge app logs and logging guidelines. No external telemetry vendor, session replay, or Forge frontend-log EAP is configured.
  • Use of customer data: We do not sell customer data or use it for advertising.

Contact Inquiries

If you contact us via email (hello@neural-void.com), we receive your email address and message content. We use this to respond to your inquiry and investigate the reported issue. Start with the error code, approximate time, and reproduction steps. Do not send passwords, API tokens, webhook URLs, or unrelated Jira content; redact screenshots before sharing them.
